# Умный кредитный кабинет предпринимателя

Веб-прототип личного кабинета предпринимателя для определения
потребности в финансировании, подбора кредитного продукта, подачи заявки
и отслеживания результата.

## Возможности

-   Регистрация и вход в личный кабинет.
-   Профиль пользователя и история заявок.
-   Анкетирование для определения потребности в финансировании.
-   Рекомендация кредитного продукта.
-   Заполнение заявки с данными компании и параметрами кредита.
-   Карточка заявки со статусом, результатом скоринга и выполненными
    проверками.
-   PostgreSQL для хранения данных.
-   Mock-сервисы для имитации внешних проверок.
-   Отдельный scoring-service с HTTP API `POST /score`.
-   Ollama как дополнительный сервис, если он включён в текущую
    конфигурацию.



## Технологии

-   Frontend: React, TypeScript, Vite.
-   Backend: Python, FastAPI.
-   База данных: PostgreSQL.
-   Контейнеризация: Docker Compose.
-   Интеграции: mock-services, scoring-service, дополнительный
    Ollama-сервис.

## Сервисы и порты

  Сервис              Назначение                     Порт хоста
  ------------------- --------------------------- -------------
  `frontend`          Веб-интерфейс                      `5173`
  `backend`           API и бизнес-логика                `8000`
  `db`                PostgreSQL                         `5433`
  `scoring-service`   Скоринговый API                    `9562`
  `ollama`            Дополнительный AI-сервис          `11434`
  `mock-services`     Имитация внешних проверок     см. Compose

Порты необходимо сверять с актуальным `compose.yaml` или
`docker-compose.yml`.

## Пользовательский сценарий

1.  Пользователь регистрируется или входит в кабинет.
2.  Просматривает профиль и историю заявок.
3.  Заполняет анкету потребности в финансировании.
4.  Получает рекомендацию продукта.
5.  Выбирает продукт и заполняет заявку, включая сведения о компании.
6.  Отправляет заявку.
7.  Backend выполняет предусмотренные проверки, вызывает скоринговый
    сервис и сохраняет результат.
8.  Пользователь отслеживает статус и результат в карточке заявки.

## Требования

-   Docker Desktop на Windows/macOS либо Docker Engine и Docker Compose
    на Linux.
-   Интернет для первоначальной загрузки Docker-образов.
-   Свободные порты, указанные в Compose.

Для запуска через Docker обычно не требуется устанавливать Python и
Node.js на компьютер.

## Запуск на Windows

Откройте PowerShell в корне проекта:

``` powershell
cd "C:\Users\fortu\OneDrive\Desktop\test\smart-credit-cabinet"
```

В корне должен находиться `.env`, если он требуется Compose. Если есть
`.env.example`, скопируйте его в `.env` и заполните значения по образцу:

``` powershell
Copy-Item .env.example .env
```

Выполняйте команду только если `.env.example` существует. Не публикуйте
`.env` с паролями и секретами.

Для обращения backend к scoring-service внутри Docker-сети используется
адрес сервиса, например:

``` dotenv
SCORING_API_URL=http://scoring-service:9562/score
```

Затем соберите и запустите сервисы:

``` powershell
docker compose up --build -d
docker compose ps
```

Откройте доступные адреса:

-   Frontend: http://localhost:5173
-   Backend API: http://localhost:8000
-   Swagger backend: http://localhost:8000/docs
-   Swagger scoring-service: http://localhost:9562/docs

Адреса будут доступны, если соответствующие порты опубликованы в
Compose.

## Полезные команды

``` powershell
# Состояние контейнеров
docker compose ps

# Логи всех сервисов
docker compose logs --tail=200

# Логи backend и скоринга
docker compose logs --tail=200 backend
docker compose logs --tail=200 scoring-service

# Пересборка frontend
docker compose up --build -d frontend

# Пересборка backend
docker compose up --build -d backend

# Пересборка всех сервисов
docker compose up --build -d

# Обычная остановка с сохранением данных томов
docker compose down

# Запуск после остановки
docker compose up -d
```

**Важно:** не используйте `docker compose down -v`, если нужно сохранить
пользователей и историю заявок. Ключ `-v` удаляет тома, в которых может
храниться база данных.

## Проверка скоринга

1.  Проверьте, что scoring-service запущен:

    ``` powershell
    docker compose ps scoring-service
    ```

2.  В отдельном окне PowerShell включите просмотр логов:

    ``` powershell
    docker compose logs -f --since=1m scoring-service
    ```

3.  Создайте и отправьте новую заявку через интерфейс.

4.  Проверьте появление новой строки:

    ``` text
    "POST /score HTTP/1.1" 200 OK
    ```

Такая строка подтверждает успешную обработку HTTP-запроса, но сама по
себе не доказывает правильность бизнес-решения и не связывает запрос с
конкретной заявкой. Для полной проверки сопоставьте время отправки,
номер заявки, результат в интерфейсе и логи backend.

Проверка доступности сервиса из контейнера backend:

``` powershell
docker compose exec backend python -c "import urllib.request; print(urllib.request.urlopen('http://scoring-service:9562/docs', timeout=5).status)"
```

Ответ `200` означает, что документация сервиса доступна из
backend-контейнера.

## Проверка сохранения истории

1.  Создайте заявку и запишите её номер.
2.  Убедитесь, что она отображается в истории.
3.  Выполните `docker compose down`.
4.  Запустите проект командой `docker compose up -d`.
5.  Войдите в тот же аккаунт и проверьте историю.

Не удаляйте тома перед этой проверкой. Сохранность зависит от
настроенного постоянного тома PostgreSQL.
