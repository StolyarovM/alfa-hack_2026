# Умный кредитный кабинет предпринимателя

## О проекте

**Умный кредитный кабинет предпринимателя** — веб-приложение, предназначенное для упрощения процесса подбора кредитного продукта и подачи заявки на финансирование малого бизнеса.

Проект разработан в рамках хакатона и представляет собой прототип личного кабинета предпринимателя. Пользователь может пройти анкетирование, получить рекомендацию по кредитному продукту, подать заявку, отслеживать этапы её рассмотрения и задать вопросы кредитному помощнику.

## Основные возможности

- **Личный кабинет** — регистрация, авторизация и доступ к пользовательским данным.
- **История заявок** — просмотр ранее созданных заявок и результатов проверок.
- **Анкета потребности в финансировании** — сбор информации для определения подходящего кредитного продукта.
- **Подбор кредитного продукта** — получение рекомендации на основе введённых данных.
- **Подача кредитной заявки** — заполнение информации о компании, финансовых показателях и запрашиваемом финансировании.
- **Отслеживание статуса заявки** — отображение текущего состояния и этапов проверки.
- **Скоринговая оценка** — передача данных в отдельный сервис скоринга и получение результата.
- **Кредитный помощник на базе языковой модели** — ответы на вопросы пользователя с учётом контекста его заявки.
- **Имитация внешних проверок** — использование mock-сервисов для демонстрации взаимодействия с внешними системами.

## Пользовательский сценарий

1. Предприниматель регистрируется или входит в личный кабинет.
2. Просматривает профиль и историю предыдущих заявок.
3. Заполняет анкету для определения потребности в финансировании.
4. Получает рекомендацию подходящего кредитного продукта.
5. Выбирает продукт и заполняет заявку с данными предприятия и параметрами кредита.
6. Отправляет заявку на рассмотрение.
7. Система выполняет предусмотренные проверки и получает результат скоринговой оценки.
8. Пользователь открывает карточку заявки и отслеживает её статус.
9. При необходимости задаёт вопросы кредитному помощнику, который формирует ответ на основе доступных данных заявки.

## Архитектура проекта

Приложение построено по клиент-серверной архитектуре и разделено на несколько компонентов.

- **Frontend** отвечает за пользовательский интерфейс, формы, отображение заявок и взаимодействие с кредитным помощником.
- **Backend** реализует API приложения, обрабатывает пользовательские запросы, управляет заявками и взаимодействует с базой данных и внешними сервисами.
- **PostgreSQL** используется для хранения данных приложения.
- **Scoring-service** выполняет скоринговую оценку и предоставляет API для работы кредитного помощника.
- **Ollama** обеспечивает запуск языковой модели, используемой для формирования ответов кредитного помощника.
- **Mock-services** имитируют внешние проверки, необходимые для демонстрации процесса рассмотрения заявки.

Взаимодействие компонентов организовано через HTTP API. Сервисы запускаются в Docker-контейнерах и взаимодействуют внутри сети Docker Compose.

## Требования для запуска

Для локального запуска необходимы:

- Docker Desktop с работающим Docker Engine либо Docker Engine и Docker Compose.
- Доступ к интернету для первоначальной загрузки Docker-образов и языковой модели, если они ещё не загружены.
- Свободные порты, указанные в конфигурации Docker Compose.

Устанавливать Python и Node.js отдельно на компьютер обычно не требуется, поскольку приложение запускается в контейнерах.

## Запуск проекта

### 1. Перейти в каталог проекта

В Windows откройте PowerShell и выполните:

```powershell
cd "C:\Users\fortu\OneDrive\Desktop\test\smart-credit-cabinet"
```

### 2. Проверить настройки окружения

Убедитесь, что в корне проекта присутствует файл `.env`, если он требуется конфигурацией Docker Compose.

Если в проекте есть `.env.example`, создайте локальную копию:

```powershell
Copy-Item .env.example .env
```

При отсутствии `.env.example` ориентируйтесь на текущую конфигурацию `compose.yaml` и переменные, используемые приложением.

**Не публикуйте `.env` в GitHub**, поскольку в нём могут находиться пароли, токены и другие конфиденциальные настройки.

### 3. Собрать и запустить контейнеры

```powershell
docker compose up --build -d
```

### 4. Проверить состояние сервисов

```powershell
docker compose ps
```

### 5. Открыть приложение

Адрес пользовательского интерфейса и API зависит от опубликованных портов в `compose.yaml`.

При текущей конфигурации ожидаются следующие адреса:

| Компонент | Адрес |
|---|---|
| Frontend | http://localhost:5173 |
| Backend API | http://localhost:8000 |
| Swagger backend | http://localhost:8000/docs |
| Scoring-service | http://localhost:9562 |
| Swagger scoring-service | http://localhost:9562/docs |
| Ollama API | http://localhost:11434 |

Если порты в конфигурации изменены, используйте фактические значения из `compose.yaml`.

## Проверка скоринга и кредитного помощника

После отправки заявки backend обращается к скоринговому сервису. Для работы кредитного помощника backend передаёт контекст заявки в endpoint `/chat`, после чего scoring-service обращается к Ollama.

Проверить работу компонентов можно по логам:

```powershell
docker compose logs --tail=100 backend
docker compose logs --tail=100 scoring-service
```

В логах scoring-service должны появляться запросы к `/score` при выполнении скоринговой оценки и к `/chat` при отправке сообщений кредитному помощнику.

Ответ `200 OK` свидетельствует об успешной обработке HTTP-запроса. Дополнительно необходимо проверять корректность отображения результата в пользовательском интерфейсе.

## Безопасность и ограничения

Проект является прототипом, созданным для демонстрации пользовательского сценария кредитования предпринимателей.

- Mock-сервисы имитируют взаимодействие с внешними системами и не гарантируют получение реальных данных.
- Результаты скоринговой модели предназначены для демонстрационных целей и не являются официальным решением банка.
- Ответы языковой модели могут содержать неточности и требуют критической оценки.
- Для промышленного использования необходимы полноценная авторизация и управление доступом, защита персональных данных, безопасное хранение секретов, журналирование, мониторинг и дополнительные проверки корректности результатов.
